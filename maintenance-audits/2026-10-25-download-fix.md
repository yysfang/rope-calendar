# 规程下载检查与修复

用户反馈手机文件页显示“文件大小：0B、正在接收文件”，未能确认具体赛事。此次检查覆盖现有 73 场赛事的全部 68 条资料引用、64 个独立附件。

## 全部线上附件

- 64 个线上文件均匿名完整取回，HTTP 200，内容非空；未发现丢失、零字节文件或内容损坏。
- PDF 24、HTML 35、DOCX 3、DOC 2。二进制文件与仓库原件完全一致；25 个 HTML 的字节差异仅为 Windows CRLF 与发布端 LF 换行，统一换行后全文一致。
- 一次 Node 并发检查中最大的约 20MB PDF 超时；后续完整重试成功，传输耗时约 37 秒。该超时不能记作附件丢失。
- 每个文件的响应类型、大小、传输用时与内容一致性记录在同目录 JSON；未修改赛事、规程原件、核查日期或统计配置。

## 定位与处理

旧代码的赛事列表、规程库、赛事详情均直接使用无文件名的 download 属性，其中 HTML 网页归档也被强制交给手机接收文件。截图与内置浏览器接收环节卡住的表现一致，但未在反馈者手机上复现，不能断言具体设备的原因。

三个入口现共用 RegulationLink。HTML 资料先显示沙箱 iframe 正文，并保留带 .html 文件名的下载及官方原文入口；PDF、DOC、DOCX 保留明确名称和真实扩展名。微信中先展示复制下载链接、可选中长按复制的链接框及系统浏览器保存指引，避免直接交给 0B 接收界面。原始官方出处保留。

## 验证

- 新增 4 项测试，包含全部 68 条引用的项目路径与非空文件校验；完整套件 35 项通过。
- 桌面与 390px 手机视口查看上海网页规程：实际正文和图片可读，无页面横向溢出，保存及原文入口可见。
- 在浏览器真实点击韩国公开赛 PDF 下载，捕获完成事件，文件以清楚的中文名称保存到 Downloads；取回文件为 1,843,694 字节，有 PDF 文件头，与仓库原件逐字节一致。
- 验证列表、规程库和详情入口；详情内打开规程后关闭子窗口，赛事详情仍保留，最外层关闭后恢复页面滚动。
- 本地专用夹具使用微信 UA 生成访问方式并呈现真实组件，检查了手机指引、完整链接、复制后的成功标签。此为兼容分支验证，不是真实微信设备测试；浏览器工具剪贴板隔离使跨界面粘贴未得到确证，故一直保留手动复制链接。
- 发布前运行完整测试、类型检查、生产构建和 diff 检查；发布后核实实际页面、规程阅读与附件响应。原生微信的接收与保存仍受其自身及网络条件影响。

维护访问使用 analytics=off，不计作自然访问。

## 发布基础设施

第一次发布的构建和上传成功，部署动作立即查询时返回 0 个附件，随后相同 API 能看到附件；重试同一任务后存在 2 个同名 github-pages 附件，部署动作拒绝继续。按照官方 upload-pages-artifact/deploy-pages 的 name/artifact_name 参数，改为每次运行及尝试独立命名，并在部署前最多等待 30 秒确认附件可见。保留所有旧产物，没有删除或覆盖。该调整不涉及网站数据或用户权限。
