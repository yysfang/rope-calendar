# 绳历基础访问统计

用户希望知道有没有人在使用网站，获得持续维护的正反馈。实际服务验收发现百度免费版事件报告已迁移后，用户明确选择“先保留百度基础统计”，本次最终范围为浏览量、访客及新老访客，面板仅本人登录可看。

## 方案与决定

网站继续使用 GitHub Pages，统计采用用户已创建的百度统计免费版站点。网站概况提供最近 7 天/30 天趋势，新老访客提供回访估算。该账号的两个基础报告实际可访问；不另建公开看板或付费分析云。

曾比较支持自定义事件的 Umami 免费版，需要另建账号；用户选择现阶段保留百度基础统计。百度旧事件报告已迁移，不按照旧文档承诺免费可看赛事或下载点击；网站不采集这些点击。

## 统计口径

- 页面浏览：初次打开和三个主视图间真实切换；筛选、翻月、刷新目录和组件重绘不算新页面。
- 访客与回访：采用服务提供的估算，不伪造精确真人数，也不把受控接入验证当自然流量。
- 上报仅使用三个固定页面地址，不发送查询参数、搜索内容、收藏清单、赛事 ID 或联系方式。

## 边界与呈现

第三方脚本异步加载，统计故障不阻断原功能。仅正式 HTTPS 项目地址启用；本地、预览、analytics=off、DNT/GPC 下不加载。页脚提供简洁说明与关闭设置；报告不公开，追踪 ID 不显示在正文。

账号、密码、Cookie 和 API 密钥不进入仓库。公开追踪代码独立配置。赛事事实、reviewedAt、原 Sites 和既有每周维护任务不变。

验收须验证真实脚本加载、三个主视图计数、禁止采集边界、关闭/恢复开关、原下载功能和手机呈现。百度静态代码检查明确不能识别 JS 文件内的接入，不能把这个提示当作运行失败或伪造检测通过。报表约有 20 分钟处理延迟，交付时区分脚本已生效与报表已有数据。
