# 绳历访问统计

用户希望知道有没有人在使用网站，获得持续维护的正反馈；已同意记录每周访客、回访、赛事详情查看、资料下载点击，并由本人查看统计面板。

## 方案与决定

网站仍由 GitHub Pages 托管。实现采用百度统计免费版，账号和绳历站点已由用户登录并创建。百度后台已有访客趋势、新老访客和事件报告，不另造静态“后台”或公开报告。这个服务选择是本轮实现判断；用户批准的是统计目标，具体账号和验证码由用户完成。

比较过 Umami Cloud：同样支持事件和回访估算，但需要另建账号和接入另一个境外统计服务。Cloudflare Web Analytics 的基础流量报告无法单独覆盖本次全部点击口径。当前选择复用已经配置好的百度统计。

## 统计口径

- 页面浏览：初次打开和三个主视图之间的真实切换；不把筛选、翻月、目录刷新、组件重绘算作新页面。
- 赛事查看：主动打开赛事详情一次，记录公开赛事名称。
- 下载点击：列表、资料库和详情里的资料链接点击，记录公开赛事名称和资料名称；表示点击，不声称文件下载完成。
- 回访与访客数：使用服务提供的新老访客及访客估算，不伪造精确真人计数。

## 边界与呈现

统计脚本异步加载，故障不阻止赛事、收藏和下载。仅正式 HTTPS GitHub 地址的本项目路径启用；本地、其他预览、维护者排除开关、浏览器 DNT/GPC 下不采集。查询参数、搜索内容、收藏清单、内部赛事 ID、调试字段不发送到自定义事件。

页脚增加简洁“访问统计”说明入口，说明第三方统计及本浏览器的关闭设置；没有公开计数器。关闭设置保存在本浏览器，刷新后生效。维护者可先使用 analytics=off 链接排除自己的反复访问。统计账号、密码、Cookie、API 密钥不进入仓库；正常公开的站点追踪代码单独配置。

赛事事实、reviewedAt、规程与原 Sites 均不改动。验收包括不重复计数、三个下载入口、真实百度脚本接入、手机布局、禁止采集的边界和生产发布。百度报表有处理延迟，最终交付区分“上报已接通”和“报表已出现数据”。
